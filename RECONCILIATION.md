Tolerances: **0.01 m²** for area delta, **0.01 m** for centroid displacement.
Why these numbers: the load never reprojects or re-derives geometry for a row that passes validation — the target `geom` is the source `geom` verbatim (same EPSG:32736 SRID). So area/centroid should match to floating-point/`numeric` rounding noise only. Any delta above these thresholds would mean the load pipeline is silently mutating geometry, which is a hard failure worth investigating, not a data-quality nuance.
Result: max area delta is within tolerance; max centroid displacement is within tolerance.

Note: this reconciliation deliberately does *not* compare `declared_area` to computed area — that divergence is a pre-existing legacy data-quality defect (the seed's "area mismatch" injection), not a load-fidelity issue, and is reported instead by `GET /qa/report`.
